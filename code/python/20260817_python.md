# Learning Points: Schema Validation With Row-Level Errors

## Problem Summary

Implement a Python function that validates customer records before loading them into a staging table.

The function must:

- separate valid and invalid records
- preserve the original order of records
- validate required fields
- validate field types and business rules
- collect multiple errors for a single record
- avoid mutating input records
- return a summary with total, valid, and invalid counts

## Key Implementation Lessons

### 1. Validate Per Record With A Fresh Error List

Each record needs its own error container.

Good pattern:

```python
for record in records:
    errors = []

    # append validation errors for this record only

    if errors:
        invalid_records.append({
            "record": record,
            "errors": errors,
        })
    else:
        valid_records.append(record)
```

This prevents errors from one record leaking into another record.

### 2. Match The Output Contract Exactly

The prompt asked for this shape:

```python
{
    "valid_records": [...],
    "invalid_records": [
        {
            "record": {...},
            "errors": [...]
        }
    ],
    "summary": {
        "total": 0,
        "valid": 0,
        "invalid": 0
    }
}
```

Small naming differences matter in coding interviews.

Avoid:

```python
{"error": {...}}
```

Prefer:

```python
{"errors": ["age type mismatch", "invalid_country"]}
```

### 3. Helpers Should Return Error Strings Or `None`

Early versions of the solution had helpers mutating an outer `error_logs` list or dict.

Less clean pattern:

```python
def validate_age(value: Any) -> bool:
    if isinstance(value, int) and value >= 0:
        return True

    error_logs.append("age type mismatch")
    return False
```

Cleaner pattern:

```python
def validate_age(value: Any) -> str | None:
    if isinstance(value, int) and not isinstance(value, bool) and value >= 0:
        return None

    return "age type mismatch"
```

Then the main loop decides what to do with the result:

```python
age_error = validate_age(record["age"])
if age_error is not None:
    errors.append(age_error)
```

This makes validators easier to test independently and avoids hidden shared state.

### 4. Be Careful With Python Type Details

In Python, `bool` is a subclass of `int`.

This means:

```python
isinstance(True, int)
```

returns:

```python
True
```

So age validation should explicitly reject booleans:

```python
def validate_age(value: Any) -> str | None:
    if isinstance(value, int) and not isinstance(value, bool) and value >= 0:
        return None

    return "age type mismatch"
```

### 5. Validate Required String Fields Explicitly

For fields like `customer_id`, do not only check whether the key exists.

This should be invalid:

```python
{"customer_id": 123}
{"customer_id": ""}
{"customer_id": "   "}
{"customer_id": None}
```

Good pattern:

```python
def validate_customer_id(value: Any) -> str | None:
    if isinstance(value, str) and value.strip() != "":
        return None

    return "customer id doesn't have the proper value or doesn't exist"
```

### 6. Date Validation Needs Both Format And Calendar Checks

Regex can check shape:

```python
^\d{4}-\d{2}-\d{2}$
```

But regex alone does not catch invalid calendar dates like:

```python
2026-02-30
```

Use `datetime.strptime` after the regex check:

```python
try:
    datetime.strptime(value, "%Y-%m-%d")
except ValueError:
    return "date_format_mismatch - date format unfit"
```

This validates both the string format and the real calendar date.

## Testing Mental Model

For validation problems, derive tests directly from the schema rules.

Use this checklist:

1. Empty input
2. One fully valid record
3. Missing required field
4. Blank required field
5. Wrong type for required field
6. Invalid enum value
7. Invalid date format
8. Invalid real-world date
9. Optional field omitted
10. Optional field present but invalid
11. Multiple errors in one record
12. Summary counts

## Tests To Include In A Coding Interview

A strong minimum test set for this problem:

- empty input returns empty lists and zero counts
- one valid record is returned in `valid_records`
- missing `status` and `signup_date` both appear in `errors`
- `customer_id` as `""`, `"   "`, `None`, or `123` is invalid
- email with no `@` is invalid
- email with two `@` characters is invalid
- status outside `active`, `inactive`, `suspended` is invalid
- `signup_date` with wrong format is invalid
- `signup_date` like `2026-02-30` is invalid
- `age = 0` is valid
- `age = -1` is invalid
- `age = True` is invalid
- lowercase or three-character `country` is invalid
- one record can collect multiple errors

Example inline assert style:

```python
if __name__ == "__main__":
    valid_record = {
        "customer_id": "cust_001",
        "email": "alice@example.com",
        "status": "active",
        "signup_date": "2026-08-14",
        "age": 34,
        "country": "DE",
    }

    assert validate_customer_records([]) == {
        "valid_records": [],
        "invalid_records": [],
        "summary": {"total": 0, "valid": 0, "invalid": 0},
    }

    assert validate_customer_records([valid_record]) == {
        "valid_records": [valid_record],
        "invalid_records": [],
        "summary": {"total": 1, "valid": 1, "invalid": 0},
    }

    result = validate_customer_records([
        {
            "customer_id": "cust_001",
            "email": "alice@example.com",
        }
    ])
    assert result["summary"] == {"total": 1, "valid": 0, "invalid": 1}
    assert "key columns(status) doesn't exist" in result["invalid_records"][0]["errors"]
    assert "key columns(signup_date) doesn't exist" in result["invalid_records"][0]["errors"]

    result = validate_customer_records([
        {
            "customer_id": "",
            "email": "bad-email",
            "status": "unknown",
            "signup_date": "2026-02-30",
            "age": True,
            "country": "de",
        }
    ])
    assert len(result["invalid_records"][0]["errors"]) == 6

    age_zero_record = {**valid_record, "age": 0}
    assert validate_customer_records([age_zero_record])["summary"]["valid"] == 1

    print("All tests passed")
```

## Interview Explanation Pattern

A strong verbal answer:

> I validate each record independently and keep a fresh list of errors per row so a single bad record does not affect others. Required fields are checked for presence first, then field-specific validators return either an error string or `None`. This makes the validators independent and easy to test. I collect all errors for a record instead of stopping at the first one, because row-level error reporting is more useful for data quality triage. Finally, I return valid records, invalid records with error details, and summary counts for observability.

## Complexity

For `n` records:

- Time: `O(n)`, because each record is checked once against a fixed set of rules
- Space: `O(n)`, because valid and invalid records are collected in output lists

## Production Follow-Ups

In production, consider:

- moving validation rules into configurable schema definitions
- emitting metrics by error type
- sampling invalid records in logs without exposing sensitive data
- writing invalid records to a quarantine table
- deciding whether validation failures should fail the batch or only warn
- versioning schema contracts with producers
- adding CI checks for schema compatibility
- tracking invalid-rate thresholds over time
- preserving raw records for replay and audit
- validating at multiple layers: ingestion, staging, and curated models
